# Security Policy

Thank you for helping keep this project and its users safe.

## Supported versions

Security fixes go into the **latest release** only. If you're on an older version, please update first and check whether the problem is still there.

## Reporting a vulnerability

**Please don't open a public issue, discussion or pull request for a security problem.**

Report it privately through GitHub instead:

1. Go to this repository's **Security** tab.
2. Click **Report a vulnerability**.

Only you and the maintainer can see the report. If GitHub isn't an option for you, say so in a public issue *without any details*, and we'll arrange another private channel.

### What to include

- What the problem is and what an attacker could do with it
- The version you tested, and your OS version
- Steps to reproduce, or a proof of concept
- Any ideas you have for a fix

Please don't include real credentials, private keys or other people's data. Redacted examples are fine.

## What to expect

This is a personal open source project with one maintainer, so these are good-faith targets rather than guarantees:

- **Acknowledgement** within 7 days
- **An initial assessment** (confirmed or not, and how severe) within 14 days
- **Updates** at least every 14 days while a fix is in progress
- **A fix or mitigation** as soon as practical, prioritized by severity

## Disclosure

We follow coordinated disclosure:

- Please give us a reasonable chance to release a fix before discussing the issue publicly. 90 days from your report is the default; we'll agree on something different if the situation calls for it.
- Once a fix is released, we publish a GitHub security advisory describing the problem and the fixed version, and request a CVE when it's warranted.
- You'll be credited in the advisory unless you'd rather not be.

## Scope

**In scope:** the code in this repository and the releases published from it.

**Out of scope:**

- Vulnerabilities in third-party dependencies or in the operating system. Please report those to their maintainers; we'll update promptly once a fix exists.
- Problems that need an already-compromised machine or account, or physical access to an unlocked device
- Social engineering, denial of service through volume, and automated scanner output without a demonstrated impact

## Safe harbor

If you make a good-faith effort to follow this policy, we won't pursue or support legal action against you for your research. Please avoid privacy violations, data destruction and service disruption, test only against systems and data you own or have permission to use, and give us reasonable time to respond before going public.
